# Local verification and manual review

- Use Codex's built-in `list_threads` and `read_thread` tools when prior setup or user expectations are unclear. Relevant history is in **Add transferable membership expiry** and **Specify token buyback protocol**. Do not ask the user to repeat setup before checking these tasks and the repository configuration.
- The established review environment is Anvil at `http://127.0.0.1:18557`, chain **31337**, and the website at `http://localhost:3110` (`/chains/31337/protocol`). Check current listeners and lifecycle records before starting or replacing services. A sandbox connection or process-inspection failure is not proof a service is down; repeat in the permitted host context.
- The upstream Robinhood mainnet RPC is already configured as `ROBINHOOD_MAINNET_RPC_URL` in `contracts/.env` (also available in `web/.env`). Load that value privately and pass it as `BBF_FORK_RPC_URL` for the fork harness. An unset harness variable is setup work, not a reason to stop verification or ask the user for an RPC. Never print credentials or load public signing keys for local verification.
- Use `scripts/test-protocol-fork.sh` / `scripts/protocol-fork/lifecycle.py`, the origin pinned in `scripts/protocol-fork/origin.json`, and a fresh retained directory under `artifacts/protocol-fork/`. The lifecycle does not source dotenv files itself. Set the execution RPC and web URLs explicitly; its generic RPC default is not the established review port. Start fork gas at **0.1 gwei**.
- Keep the fork and webpage running when handing work back for verification. The page must use the current local deployment and its generated browser environment. A unit-test run, a public-chain page, or an HTTP 200 without working contract reads is not a manual-review handoff.
- Preserve existing manual-review state while testing. Use snapshots and restore them after transaction scenarios. Use a separate temporary fork for destructive scenarios; do not reset another running review session. If changed immutable contracts require a fresh deployment, recreate the review fixtures and signer access before handoff.
- Review fixtures include funded memberships and gas/token balances for `0x467172992E0aBa58411d14eC8b174167B0e359a6` and `0xbE0032Fc13718aB554236c3Bd9446F6b5c9b9027`. The second wallet must be a Safe signer with threshold 1 on the disposable review fork. Use `web/scripts/seed-protocol-review.ts EVIDENCE FIRST_WALLET SECOND_WALLET` after automated transaction scenarios: it restores the established eight-membership fixture and signing access. The requested scale is at least **$250 of first-month buybacks**; this fixture supplies **300 USDG + 0.02 WETH** of first-month protocol fees, with at least **1,000 USDG + 1 WETH** and gas remaining per wallet. Verify actual membership ownership, balances, and Safe threshold after setup.
- Fresh guarded-release deployments remain `OperatorGuarded`. Do not silently enable permissionless buybacks to make a demo work. Operator terms remain off-chain; public demo policies require explicit selection. See `scripts/protocol-fork/README.md`.
- Report the verification actually performed and leave usable local URLs and retained evidence. Public testnet/mainnet deployment is a separate authorization.
